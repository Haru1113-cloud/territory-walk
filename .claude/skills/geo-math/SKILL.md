# いつ読むか

`lib/geo/` 以下のファイル（距離計算・面積計算・軌跡→領土の判定ロジック）を
新規作成・修正・レビューするとき、または「面積の値がおかしい」「輪が閉じない」
といった不具合を調査するときに読む。UI実装やウィジェットのレイアウトだけを
触るときは読まなくてよい。

---

## 参照元

`prototype/territory-walk-prototype.html` の以下の関数が検証済みの元ロジック。
Dart移植時も考え方（アルゴリズムの選択・閾値の意味）は変えない。

- `haversineDistanceMeters`
- `toLocalXY`
- `shoelaceAreaSquareMeters`
- `tryAddPoint` 内のブレ除去フィルタ・自動クローズ判定

## 1. ハバーサイン公式（2点間の距離）

地球を半径6371kmの球とみなし、2つの緯度経度から距離（メートル）を求める。

```
R = 6371000
dLat = toRad(b.lat - a.lat)
dLng = toRad(b.lng - a.lng)
h = sin²(dLat/2) + cos(lat1)・cos(lat2)・sin²(dLng/2)
c = 2・atan2(√h, √(1-h))
distance = R・c
```

Dartでは `dart:math` の `sin`/`cos`/`atan2`/`sqrt` でそのまま実装できる。
外部パッケージ（例: `latlong2` の `Distance`）を使ってもよいが、値の検証は
プロトタイプの計算結果と突き合わせること。

### 移動距離（`pathDistanceMeters`）

「今回の散歩の移動距離」は、プロトタイプにはない後付けの指標。軌跡（点の配列）の
連続する点同士のハバーサイン距離を単純に合計するだけで求める（`lib/geo/distance.dart`）。
輪として閉じているかどうかは問わない。呼び出し側（Controller）は、輪が閉じて
`trail`がリセットされても影響を受けない「セッション全体の軌跡」を別に保持し、
そちらを渡すこと（詳細は`flutter-conventions` skillのController節を参照）。

## 2. 緯度経度 → 平面座標への変換（`toLocalXY`）

靴ひも公式は平面座標を前提とするため、緯度経度をそのまま使わず、
基準点（origin、通常は軌跡の最初の点）からの相対距離（メートル）に変換する。

```
metersPerDegLat = 111320
metersPerDegLng = 111320 * cos(origin.lat in rad)

x = (point.lng - origin.lng) * metersPerDegLng
y = (point.lat - origin.lat) * metersPerDegLat
```

これは数百m〜数km程度の散歩コースを想定した近似（局所的にはほぼ平面とみなせる）。
日本全体をまたぐような広域では誤差が大きくなるが、本アプリのスコープでは問題にならない。

## 3. 靴ひも公式（Shoelace formula、多角形の面積）

`toLocalXY` で変換した平面座標の配列（順序が軌跡の順番になっていること）から
面積（平方メートル）を求める。

```
sum = 0
for i in 0..n-1:
    current = points[i]
    next = points[(i+1) % n]
    sum += current.x * next.y - next.x * current.y
area = abs(sum) / 2
```

多角形が閉じていなくても（配列の最後と最初をつなぐ前提で）動作する
= 軌跡の配列をそのまま渡してよく、事前に「最初の点を最後にも追加する」処理は不要。

## 4. 輪の自動クローズ判定

軌跡ポイントを1つ追加するたびに、以下の条件を両方満たしたら「輪が閉じた」と
みなし、その時点の軌跡全体を領土として確定する。

- 軌跡ポイント数が `MIN_POINTS_TO_CLOSE`（プロトタイプでは5）以上である
  （スタート直後に自分自身との距離0で誤って閉じるのを防ぐため）
- 現在地とスタート地点（軌跡の最初の点）とのハバーサイン距離が
  `CLOSE_RADIUS_METERS`（プロトタイプでは15m）未満である

輪が閉じたら、その軌跡から面積を計算し、領土リストに追加し、合計面積に加算する。
その後、軌跡をリセットして次の輪を歩き始められるようにする（スタート/ストップの
やり直しは不要＝連続して複数の領土を獲得できる）。

## 5. GPSのブレ除去フィルタ（最小移動距離フィルタ）

新しい位置情報（GPS）を受け取ったとき、
直前に記録したポイントとの距離が `MIN_MOVE_METERS`（プロトタイプでは5m）未満
であれば、そのポイントは軌跡に追加せず無視する。

これにより、GPSの測位誤差による細かい位置のブレが軌跡や面積計算に
悪影響を与えるのを防ぐ。フィルタは「軌跡に追加するかどうか」だけに使い、
地図上の現在地マーカーの表示自体は毎回更新してよい（フィルタするのは
あくまで軌跡データ）。

## 閾値のまとめ

| 定数 | プロトタイプでの値 | 意味 |
|---|---|---|
| `minMoveMeters` | 5m | これ未満の移動はGPSのブレとして無視 |
| `closeRadiusMeters` | 15m | スタート地点からこの距離以内で輪を閉じる |
| `minPointsToClose` | 5 | 輪のクローズ判定を開始する最低ポイント数 |

Dart移植時もこれらの値は同じ場所（`lib/geo/territory_constants.dart` を想定）に
まとめ、マジックナンバーとして散らさないこと。
