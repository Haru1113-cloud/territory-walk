# いつ読むか

`lib/widgets/territory_map.dart` や地図の見た目（色・線の太さ・塗りつぶし）を
新規作成・修正するときに読む。距離や面積の「数値」の計算ロジックを触るときは
代わりに `geo-math` skillを読む。

---

## 地図ライブラリ・ベースマップ

`flutter_map`（APIキー不要）を使う。

- タイルレイヤー: CARTOの Positron（ラベルなし版）
  `https://{s}.basemaps.cartocdn.com/light_nolabels/{z}/{x}/{y}{r}.png`
  （帰属表示: © OpenStreetMap contributors © CARTO）
- 通常のOSM標準タイル（`tile.openstreetmap.org`）ではなく、あえて
  「地名・道路名などの文字ラベルを持たないタイル」を選んでいる。
  理由: 軌跡（差し色）と領土（ビビッドな塗り）を目立たせる「白ベース+
  差し色のポップな見た目」にしたいため、背景の地図はできるだけ情報量を
  減らし、白っぽくシンプルにする（`docs/DESIGN.md`のデザイン方針を参照）。
  細かい地名が必要な操作は今回のスコープにない。
- 初期表示位置: 現在地が取得できればそこ、テストモードや未取得時は
  固定のデフォルト座標（例: 東京駅付近 `35.681236, 139.767125`）にフォールバックする。
- 初期ズームレベル: 17前後（徒歩でのテリトリー確定が見て分かる縮尺）。

## レイヤー構成（下から順に）

1. タイルレイヤー（地図本体）
2. 確定済み領土のポリゴン群（`territories` を全件描画）
3. 記録中の軌跡（`trail`、まだ確定していない線）
4. 現在地マーカー（GPSモードのみ。テストモードでは不要）

領土ポリゴンは「確定済みで動かない」ため下、軌跡は「今まさに伸びている線」
なので上に重ねる。この順序を変えると、軌跡が領土の下に隠れて見えなくなる。

## 配色（デジタル庁デザインシステムのトークン準拠）

配色・角丸の定数は `lib/widgets/app_style.dart` の `AppColors` に集約してあり、
地図・パネルの両方がこれを参照する（色コードをファイルごとに書き散らさない）。

値は「デジタル庁デザインシステム」の公式トークンパッケージ
`@digital-go-jp/tailwind-theme-plugin`(npm, v1.0.1時点)の
`dist/v4.css` から採った実際のトークン値。ページ上のドキュメントには
HEXコードが載っていないため、パッケージを取得してCSS変数から直接確認した
（Figmaデザインデータが一次情報だが、CLI環境からはこの方法が確実）。
バージョンが上がってトークン値が変わった場合はこの節も更新すること。

| 要素 | 色 | DADSトークン名 | 用途 |
|---|---|---|---|
| 軌跡（記録中） | `AppColors.primary` `#0017C1`（線・太さ6・角丸キャップ） | `key/blue-900` | まだ確定していない軌跡。「進行中の操作」を表すプライマリ色 |
| 領土（確定済み・線） | `AppColors.territoryBorder` `#197A4B`（線・太さ3） | `success-2` | ポリゴンの輪郭 |
| 領土（確定済み・塗り） | `AppColors.territoryFill` `#259D63`（不透明度0.55） | `success-1` | ポリゴンの内部。「輪を閉じて確定=成功」の意味を色にも持たせている |
| 現在地マーカー | `AppColors.primary` | `key/blue-900` | GPSモードのみ表示 |
| 本文・見出し | `AppColors.ink` `#1A1A1A` | `solid-gray-900` | |
| 補助テキスト | `AppColors.inkMuted` `#767676` | `solid-gray-536` | 白背景でコントラスト比4.5:1を確保 |
| 枠線 | `AppColors.border` `#B3B3B3` | `solid-gray-300` | アウトラインボタン・トグルの枠線 |
| フォーカス強調 | `AppColors.focus` `#0877D7` | `focus-blue` | `ThemeData.focusColor` |

軌跡=プライマリ色（操作中）、領土=成功色（確定＝ポジティブな結果）という
意味づけを色にも持たせている。複数の領土を色分けする要件は現時点でない
（全て同じ配色でよい）。将来、対戦機能で「プレイヤーごとの色」を導入する
余地は残すが、今回は`Territory`モデルに色情報を持たせる実装はしない
（`DESIGN.md`の「今回実装しない範囲」を参照）。

## 角丸・形状

DADSの角丸トークンを踏襲する。ボタン・SegmentedButton・アウトラインの
角は`AppColors.radiusSmall`（8px、DADSトークン`radius-8`）の
`RoundedRectangleBorder`にする（ピル型のスタジアム形状は使わない。
DADSのボタンはアウトライン付きの角丸長方形が基本のため）。ボトムシート
（`ControlPanel`）の上端のみ`AppColors.radiusLarge`（24px、
`radius-24`）を使い、コンテナとしての存在感を持たせる。

## 操作パネルの配置

`ControlPanel` は画面下部にボトムシート状（上端のみ角丸、白背景、影）で
固定表示する。地図の上部を覆わないようにし、スマートフォンを片手で
持ったときの親指の可動範囲（画面下部）にボタンを置くことで操作しやすくする
（当初は画面上部にオーバーレイしていたが、地図が隠れやすく操作もしにくい
ため下部固定に変更した）。

パネル内の要素は上から: 合計獲得面積（最も大きく太い文字で「主役」として
見せる）→ モード切替（角丸長方形のSegmentedButton）→ スタート/ストップ・
輪を閉じるボタン（どちらも角丸長方形、DADSの角丸トークンを参照）の順。

## 描画の更新タイミング

- 軌跡: `trail` にポイントが追加されるたびに `Polyline` を再構築する。
  ポイント数が数百程度まではパフォーマンス上の問題にならない想定。
  シンプルさを優先し、差分更新のような最適化は行わない。
- 領土: 輪が閉じたタイミングで `territories` に1件追加し、その1件分だけ
  新しい `Polygon` として描画に加える（既存の領土ポリゴンを毎回全部
  作り直す必要はないが、シンプルさ優先で全件再描画でも構わない。
  領土の件数がアプリのスコープ上多くなりすぎないため、パフォーマンス上の
  実害は出ない想定）。

## 現在地マーカー（GPSモードのみ）

シンプルな `Marker` + アイコン（例: `Icons.my_location`）でよい。
向き（進行方向）の表示や精度円（accuracy circle）の描画は今回のスコープ外。
