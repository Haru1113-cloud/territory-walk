# いつ読むか

`lib/widgets/territory_map.dart` や地図の見た目（色・線の太さ・塗りつぶし）を
新規作成・修正するときに読む。距離や面積の「数値」の計算ロジックを触るときは
代わりに `geo-math` skillを読む。

---

## 地図ライブラリ・ベースマップ

`flutter_map`（APIキー不要）を使う。

- タイルレイヤー: CARTOの Positron（ラベルなし版、明るい配色）
  `https://{s}.basemaps.cartocdn.com/light_nolabels/{z}/{x}/{y}{r}.png`
  （帰属表示: © OpenStreetMap contributors © CARTO）
- 通常のOSM標準タイル（`tile.openstreetmap.org`）ではなく、あえて
  「地名・道路名などの文字ラベルを持たない、明るく淡い配色のタイル」を
  選んでいる。理由: 「情報を伝える地図」ではなく「柔らかい自然光の下の
  舞台」にしたいため（`docs/DESIGN.md`のビジュアル方針を参照）。軌跡
  （深緑の線）と領土（紫の塗り）を、明るい舞台の上でよく映えるように
  する狙い。2026-07にダーク×グロー方針からこの明るいトーンへ
  切り替えた（それ以前はダーク配色のDark Matterを使っていた）。
  細かい地名が必要な操作は今回のスコープにない。
- タイルはそのまま表示せず、`ColorFilter.mode(AppColors.mapTint, BlendMode.color)`
  で単色トーン(デュオトーン)に染めてから表示する(`territory_map.dart`)。
  生のCARTOタイルは情報密度が高く「地図製品」に見えてしまうため、明度だけ
  残して色相を1色に統一し、フラットな「舞台の書き割り」のように単純化する
  狙い。`BlendMode.color`は元タイルの明度を保持したまま色相だけ置き換える
  ため、明るい基調のタイル（Positron）でなければ暗いままになる点に注意
  （ダーク配色のタイルには使えない）。
- 初期表示位置: 現在地が取得できればそこ、未取得時は
  固定のデフォルト座標（例: 東京駅付近 `35.681236, 139.767125`）にフォールバックする。
- 初期ズームレベル: 17前後（徒歩でのテリトリー確定が見て分かる縮尺）。

## レイヤー構成（下から順に）

1. タイルレイヤー（地図本体）
2. 確定済み領土のポリゴン群（`territories` を全件描画）
3. 記録中の軌跡（`trail`、まだ確定していない線）
4. 現在地マーカー

領土ポリゴンは「確定済みで動かない」ため下、軌跡は「今まさに伸びている線」
なので上に重ねる。この順序を変えると、軌跡が領土の下に隠れて見えなくなる。

## 配色（クリーム系の明るいトーン）

配色・角丸の定数は `lib/widgets/app_style.dart` の `AppColors` に集約してあり、
地図・パネルの両方がこれを参照する（色コードをファイルごとに書き散らさない）。

2026-07にユーザー要望で、それまでの「暗い舞台の上でネオンが光る」ダーク×
グローのトーンから、生成り・クリーム系の明るく自然なトーンへ全面的に
差し替えた（ゴルフアプリのUIを参考に、ただし模倣はせず既存の色の意味づけ
の枠組みの中で咀嚼した）。「情報を伝える地図」ではなく「柔らかい自然光の
下の舞台」を目指す方針（詳細は`docs/DESIGN.md`）。

| 要素 | 色 | 用途 |
|---|---|---|
| アプリ背景 | `AppColors.background` `#F6F3EC` | 生成りに近い温かいオフホワイト |
| パネル・カード面 | `AppColors.panel` `rgba(255,255,255,0.96)` | ほぼ不透明の白ガラス調。背後にBackdropFilterでぼかしを重ねる |
| 軌跡（移動ルート） | `AppColors.trail` `#1C8F63`（深緑） | 線・グロー・「今回の距離」の主役表示・スタートボタンなど、「進行中の行動」を表す箇所全般 |
| 領土（獲得エリア） | `AppColors.territory` `#6C4FE0`（紫） | 塗り・輪郭・グロー・獲得トーストの背景など、「確定した領土」を表す箇所全般 |
| バッジ・達成 | `AppColors.badgeAccent` `#E0A233`（琥珀） | バッジチップ・バッジ画面のアイコン色 |
| 本文・見出し | `AppColors.ink` `#201C16` | 温かみのある濃いチャコール |
| 補助テキスト | `AppColors.inkMuted` `#7A7568` | 中間トーンのグレー |
| 枠線 | `AppColors.border` `#E3E0D3` | 明るい背景の上で控えめな区切り線 |
| アクセント上の文字 | `AppColors.onAccent` `#FFFFFF` | trail/territory/badgeAccentのような中〜濃いトーンの塗りの上に乗せる文字色（白文字が読みやすい） |

色の意味づけ: **軌跡=深緑（進行中）、領土=紫（確定・獲得）、バッジ=琥珀
（達成）** の3系統で統一し、UI上のどこに出てきても「これは軌跡に関する
表示だ」「これは領土に関する表示だ」と色だけで判別できるようにしている。
複数の領土を色分けする要件は現時点でない（全て同じ配色でよい）。将来、
対戦機能で「プレイヤーごとの色」を導入する余地は残すが、今回は`Territory`
モデルに色情報を持たせる実装はしない（`DESIGN.md`の「今回実装しない範囲」
を参照）。

## グロー（光彩）表現

flutter_mapの`Polyline`/`Polygon`にはCSSのbox-shadow相当のプロパティが
ないため、「同じ座標に対して太さ・不透明度の異なる線/塗りを複数重ねる」
ことでグローに見せかけている（`lib/widgets/glow_line_style.dart`参照）。

- 軌跡: 外側に太く不透明度の低い深緑の線、内側に細く不透明度の高い
  深緑の線を重ねた2層構成。
- 領土: 外側に太く不透明度の低い紫の輪郭（ハロー）、内側に本来の塗り+
  輪郭を重ねた2層構成。

真のぼかし（ガウシアンブラー）ではなく「縁が滲んで見える」簡易表現である
ことを許容する（実装のシンプルさを優先。ユーザー要望でもこの簡略版が
明示的に許可されている）。

## 角丸・形状

ボタン・SegmentedButton・アウトラインの角は`AppColors.radiusSmall`（8px）の
`RoundedRectangleBorder`にする。ボトムシート（`ControlPanel`）の上端のみ
`AppColors.radiusLarge`（24px）を使い、コンテナとしての存在感を持たせる。

## 操作パネルの配置

`ControlPanel` は画面下部にボトムシート状（上端のみ角丸、`BackdropFilter`で
ぼかした白っぽい半透明のガラス調、影）で固定表示する。地図の上部を覆わないように
し、スマートフォンを片手で持ったときの親指の可動範囲（画面下部）にボタンを
置くことで操作しやすくする（当初は画面上部にオーバーレイしていたが、地図が
隠れやすく操作もしにくいため下部固定に変更した）。最上部には「これはシートで
ある」ことを一目で伝える飾りのドラッグハンドル（実際のドラッグ操作は無い）を
置く。

パネル内の要素は上から: ドラッグハンドル → **今回の散歩の距離**（軌跡と
同じ深緑系＋テキストグローで、最も大きく「主役」として見せる。
`TeraWalkController.sessionDistanceMeters`。同じ行の右上に「現在地に戻る」
丸型ボタンを配置）→ 獲得面積(累計)・軌跡ポイント数・領土件数（3つの
ピル型チップに分けて表示、`_StatChip`）→ 獲得済みバッジのチップ行
（`BadgeChipRow`、未獲得なら非表示）→ スタート/ストップ・輪を閉じる
ボタンの順（「輪を閉じる」はスタート地点から100m以内のときだけ表示、
`TeraWalkController.isNearStartPoint`）。

地図側には、AppBar下に浮かせたガラス風のズームコントロール（`+`/`-`、
`map_zoom_controls.dart`）を別途配置している。頻繁に触る地味な操作なので、
「現在地に戻る」ボタンのようなアクセントカラーの塗りではなく、
ニュートラルな`AppColors.panel`のガラス面にして役割の重みを分けている。

## ボタンの見た目（`_GlowButton`）

主要な操作ボタン（スタート/ストップ・輪を閉じる）は、地味なアウトライン
ボタンではなく、アクセントカラーで塗った上にボタンと同色のグロー（影）を
敷いた`_GlowButton`（`control_panel.dart`内のプライベートウィジェット）を
使う。「押したくなる見た目」を優先し、無効時（`onPressed: null`）はグローを
弱めて押せないことも見た目で伝える。

- スタート/ストップ: `AppColors.trail`（深緑）。「今動いている操作」の
  意味づけに合わせた。
- 輪を閉じる: `AppColors.territory`（紫）。押すと領土が確定する操作なので
  領土の色に合わせた。

「移動距離を主役、獲得面積は脇役」という優先度はユーザー要望による意図的な
判断（`lib/widgets/control_panel.dart`の`_DistanceHero`）。面積を主役から
降格させたのは、テラウォークの体験として「今どれだけ歩いたか」の方が
散歩中にリアルタイムで気になる指標だと判断したため。距離・面積の文字列化は
`lib/widgets/format.dart`の`formatDistance`/`formatArea`に集約してあり、
振り返り画面（`history_screen.dart`等）でも同じ関数を使い回す。

## 描画の更新タイミング

- 軌跡: `trail` にポイントが追加されるたびに `Polyline` を再構築する。
  ポイント数が数百程度まではパフォーマンス上の問題にならない想定。
  シンプルさを優先し、差分更新のような最適化は行わない。
- 領土: 輪が閉じたタイミングで `territories` に1件追加し、その1件分だけ
  新しい `Polygon` として描画に加える（既存の領土ポリゴンを毎回全部
  作り直す必要はないが、シンプルさ優先で全件再描画でも構わない。
  領土の件数がアプリのスコープ上多くなりすぎないため、パフォーマンス上の
  実害は出ない想定）。

## 現在地マーカー（GPSモードのみ）

シンプルな `Marker` + アイコン（例: `Icons.my_location`）でよい。
向き（進行方向）の表示や精度円（accuracy circle）の描画は今回のスコープ外。
